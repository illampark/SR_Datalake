# SR DataLake — 2026-08-10 작업 로그

## 요약
DB 커넥터에 **소스 테이블 컬럼 코멘트(주석) introspection** 기능 추가. 기존에는 DB
커넥터가 `SELECT *` 로 데이터 행만 수집하고 컬럼 스키마/코멘트는 전혀 가져오지 않았음.
이제 테이블 등록 시 컬럼명·타입·NULL여부·PK·코멘트를 조회·저장하고, 데이터 카탈로그
`schema_info` 로 노출한다. MySQL/MariaDB · PostgreSQL 지원.

## 변경 파일 (5)
- `backend/services/benthos_manager.py` — `introspect_db_columns()` 신설.
  - MySQL/MariaDB: `information_schema.COLUMNS` (COLUMN_TYPE, IS_NULLABLE, COLUMN_KEY, COLUMN_COMMENT).
  - PostgreSQL: `information_schema.columns` + `col_description(regclass, ordinal_position)` +
    PK 조인. schema 는 `connector.schema_name` 없으면 `public`.
  - 반환: `[{name,type,nullable,comment,isPrimary}]`. Oracle/MSSQL 은 명시적 미지원 메시지.
- `backend/routes/collector_db.py`
  - `POST /api/connectors/db/columns` — 폼 자격증명으로 조회(신규 등록 화면, 저장 전).
  - `POST /api/connectors/db/<id>/columns` — 저장된 자격증명으로 조회(수정 화면, 비번 재입력 불필요).
  - `_normalize_tables_input` 이 `columns` 배열 보존(`_normalize_columns` 신설) → `config.tables[].columns` 저장.
  - update 시 `sync_connector_schema_info` 로 카탈로그 schema_info 갱신.
- `backend/services/catalog_sync.py` — `build_schema_info_from_tables()` + `sync_connector_schema_info()`.
- `backend/services/metadata_tracker.py` — `_auto_create_connector_catalog` 이 db 커넥터
  카탈로그 생성 시 config.tables 컬럼 스키마를 `schema_info` 로 초기화.
- `templates/collection/db_connector.html` — 테이블 행에 "컬럼 조회" 버튼 + 컬럼·주석
  표 렌더(`fetchColumns`/`renderColumns`). 저장 payload 에 columns 포함, 수정 화면 재현.

## 검증
- 5개 파일 `py_compile` 통과.
- PG introspection: DGX `sdl-postgres` 에 코멘트 포함 임시 테이블 생성 후, 수정한
  `introspect_db_columns` 를 **sdl-app 컨테이너 안에서 실제 실행** → 컬럼 3개 + 한글 코멘트
  + PK 정확히 반환 확인. 없는 테이블/미지원 DB 오류 경로도 확인.
- **발견·수정한 버그**: PG 쿼리의 `format('%I.%I', ...)` 리터럴 `%I` 가 psycopg2 파라미터
  치환과 충돌(`tuple index out of range`). `%%I.%%I` 로 이스케이프하여 해결. (psql 단독
  실행에선 드러나지 않고 psycopg2 경유에서만 발생 → 컨테이너 내 실제 실행으로 포착.)

## 스키마/마이그레이션
- 신규 컬럼/테이블 없음. 컬럼 스키마는 `DbConnector.config` (JSON) 에, 카탈로그 노출은
  기존 `DataCatalog.schema_info` (Text) 재사용 → **DB 마이그레이션 불필요.**

### 발견

- **Benthos 는 컨테이너 재배포 시 복원되지 않는다.** `app.py` 에 기동 시 복원 로직이
  없고 `worker_reconciler` 는 로컬 워커와 파이프라인만 조정한다(Benthos 계열 제외).
  커넥터 status 는 `running` 으로 남아 DB 만 보면 정상으로 보인다.
- **`_benthos_proc` 가 gunicorn 워커별 전역 변수다.** `is_running()` 이 HTTP `/ready`
  보다 프로세스 핸들을 먼저 검사해, 살아 있어도 다른 워커에서는 False 를 반환한다.
  → restart 마다 유령 인스턴스가 생긴다.
- **`internal_rdbms_sink` 의 `flatten` 매핑은 소스에 `id` 컬럼이 있으면 깨진다.**
  sink 가 `CREATE TABLE (id SERIAL PRIMARY KEY, <소스컬럼>)` 을 만들기 때문에
  `column "id" specified more than once` 로 실패한다. FDC 두 테이블이 해당.
- **커넥터의 `batchSize` 설정은 무시된다.** customSql 에 `LIMIT 1000` 이 하드코딩돼
  있어 config 값이 적용되지 않는다.
- **sink 는 메시지마다 PG 커넥션을 새로 연다.** 실측 건당 7ms ≈ 144건/s.
  버스트가 mosquitto 기본 큐(1000)를 넘기면 QoS 1 이어도 드롭된다.
  단독·소량 버스트는 무손실(MES 140/140, VMS 565/565)이었고, 한 콜백이 두 파이프라인에
  2,000건을 동시에 밀어넣을 때만 유실됐다.
- **`flush_all_sink_buffers` 는 파이프라인 정지 시에만 호출된다.** 시간 기반 flush 가
  없어 batch 모드는 소량 테이블(결함코드 5행)이 영구히 버퍼에 갇힌다.
- **스테이징 `inpark` 은 sudo 그룹이지만 무암호 실행이 안 된다.** `sudo -l` 의
  `(ALL) NOPASSWD: ALL` 뒤에 오는 `(ALL : ALL) ALL` 규칙이 이긴다.
- **`server_info.txt` 의 프로덕션 비밀번호가 실제와 다르다.** 같은 사실이 로컬
  `server_info.txt` · 스테이징 `~/server_info.md` · 프로덕션 `~/BUILD.md` 세 곳에
  각기 다르게 낡아 있다 → `docs/runbook/environments.md` 로 단일화.
