### 스테이징은 이 서버의 빌드 호스트가 될 수 없다

스테이징은 `x86_64`, 신규 서버는 `aarch64`. `deploy/scripts/01_build_and_export.sh`
를 스테이징에서 실행해 반입하는 흐름은 성립하지 않는다. DGX 와 동일하게
**같은 커밋을 받아 자체 빌드**했다.

### 인터넷 부재 — 원인은 기본 게이트웨이

설치 착수 시 신규 서버는 외부망이 전부 막혀 있었다(DNS 해석 실패 · `8.8.8.8` ICMP
100% 손실 · `docker pull` 실패). 같은 서브넷의 DGX 와 비교해 차이가 하나였다.

| | 신규 `192.168.1.18` | DGX `192.168.1.99` |
|---|---|---|
| default gw | `192.168.1.254` (DHCP) | `192.168.1.1` (static) |
| DNS | `192.168.1.254` | `168.126.63.1` |
| 인터넷 | ✗ | ✓ |

임시 호스트 경로(`ip route replace 8.8.8.8/32 via 192.168.1.1`)로 경로를 검증했다
— ping 33~49ms, `168.126.63.1` 로 `github.com` 해석 성공. 임시 경로는 즉시 원복했다.

이후 DHCP 서버 쪽이 올바른 값을 주기 시작해 해결됐다. **호스트에 고정한 것이 아니다**
— 현재도 `proto dhcp`, NM 은 `ipv4.method=auto` 에 routes/dns 비어 있음. 공유기가
다시 `.254` 를 주면 재발한다. DGX 처럼 고정해 두는 것이 안전하다.

   디렉터리를 만들어 MinIO 가 기동 실패한다. 배포 가이드에 빠진 단계다.
4. `.env` 생성(600) — 비밀번호 3종 무작위. `SDL_PORT=5001`.
5. 베이스 이미지: `postgres:16-alpine`·`eclipse-mosquitto:2` pull,

6. `docker build -t sdl-app:latest .` · `docker build -t sim-all:latest sim-all/`

  2개로 정상이라 기능 영향은 없으나, 시드를 멱등으로 만들 여지가 있다.

  이력 추적이 없어 향후 스키마 변경 시 환경 간 차이를 검출할 수단이 없다.

  비어 있다. 테넌트 스코프 필터로 보이나 확인하지 않았다.
