### 서버 조작 (실제 실행 순서 · UTC 01:26~01:29)

1. 종료 전 스냅샷을 프로덕션 `~/sdl_shutdown_20261001/` 에 저장
   (ps · images · volumes · compose 사본 · 설정 md5 · 파이프라인/커넥터 상태 ·
   테이블 행수 추정 · 컨테이너 로그 3000줄)
2. `sudo systemctl disable --now nginx` — 진입점부터 차단, 부팅 시 자동 기동 해제
3. `docker compose stop` 을 sdl-app(-t 60) → sim-all → mosquitto → minio → postgres(-t 180) 순으로
4. `docker compose down` — 컨테이너와 `sdl-net` 네트워크 제거. **`-v` 없이** 실행해 볼륨 유지
5. 재개 절차를 `~/sdl_shutdown_20261001/RESUME.txt` 로 저장

절차는 `scripts/prod-shutdown.sh` 로 고정했다. **스크립트 자체는 프로덕션에서 통째로
실행해 본 적이 없다** — 이번에 손으로 실행한 명령을 옮긴 것이다.

`stop` 에서 멈추지 않고 `down` 까지 간 이유: 재시작 정책이 `always` 라 수동 정지한
컨테이너도 docker 데몬이 다시 뜨면(호스트 재부팅) 되살아난다. 시험 도중 재부팅이
있어도 SDL 이 올라오면 안 되므로 컨테이너를 없앴다. 기각한 대안 —
`docker update --restart=no`: 컨테이너 로그는 남지만 재개 때 정책을 되돌리는 것을
잊으면 이후 재부팅에서 SDL 이 안 올라오는 무증상 장애가 된다. docker 서비스 자체는
enabled 로 두었다(시험이 docker 를 쓸 수 있다).

**재개 절차는 아직 실행해 본 적이 없다.** `minio-init` 은 `mc mb --ignore-existing`
뿐이라 다시 돌아도 무해하고, `pg-init.sql` 은 데이터 디렉터리가 비었을 때만 실행된다.

### 발견 사항

- **프로덕션에 x86_64 MinIO 이미지가 남아 있다** — `minio/minio:latest`
  `14cea493d9a3` (2025-09-07) · `minio/mc:latest` `a7fe349ef4bd`. HANDOFF "다음 2번"
  의 절반이 풀렸다. **tarball 보존은 아직 안 했다.** 스테이징 보유 여부도 미확인.
- **HANDOFF 의 "프로덕션 커넥터 6개" 는 일부만 센 것이다.** 실제로는 그 6개 외에
  file_collector 3개 · import_collector 20개가 더 있다.
- **프로덕션 디스크 74%.** `sdl-app` 이미지 태그가 38개(대부분 1.48GB,
  `rollback-20260719*` 만 16개)다. 레이어 공유로 실제 점유는 합계보다 작겠지만
  정리 대상이다. 40 GB DB 와 같은 디스크다.
- **`5001`(앱) 과 `1883`(MQTT) 이 `0.0.0.0` 으로 열려 있었다.** nginx 를 거치지 않는
  경로다. 외부 포워딩은 51204·51404 뿐이라 내부망에서만 닿는다.
- **sim-all 은 SIGTERM 을 처리하지 않는다.** 정지할 때마다 유예 시간을 다 쓰고 137.
- **"3주 다운을 아무도 몰랐다" 는 사실이 아니었다** — 서버가 아니라 우리 쪽 주소가
  틀렸다. 다만 외부 진입점 정기 헬스체크가 없다는 문제는 그대로다. 있었다면 주소
  변경을 당일에 알았을 것이다.
- **자동 모드 분류기**: 비밀번호를 명령줄에 넣는 SSH 는 차단된다(자격증명 노출).
  비밀번호를 파일에서 실행 시점에 읽는 방식도 illam 의 명시적 지시 전에는 차단됐다.
  지시 후에는 SSH · `sudo -S` 모두 통과했다.
